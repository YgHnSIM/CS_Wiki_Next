## 개요

[[중간 표현]](intermediate representation, IR)은 [[컴파일러]]가 [[소스 프로그램]]을 읽은 뒤 바로 특정 기계의 [[목적 프로그램]]으로 변환하지 않고, 분석·변환·코드 생성을 위해 사용하는 프로그램 표현이다. 좋은 중간 표현은 원래 프로그램에서 필요한 제어 흐름·데이터 흐름·형식 정보를 남기면서도, 여러 대상 기계에 맞는 변환을 적용할 수 있어야 한다.

[[LLVM - A Compilation Framework for Lifelong Program Analysis and Transformation|LLVM]]의 SSA 기반 표현은 값의 정의와 사용 관계를 명시해 언어 독립적인 분석과 변환을 가능하게 한다. [[TVM - An Automated End-to-End Optimizing Compiler for Deep Learning|TVM]]은 계산 그래프, 텐서 연산 표현, 저수준 루프 프로그램처럼 서로 다른 추상화 수준의 표현을 연결해, 그래프와 연산자 수준 최적화를 구분한다.

## 왜 표현을 한 단계 더 두는가

중간 표현은 프런트엔드와 백엔드의 책임을 나눈다. 프런트엔드는 언어의 문법·형식·의미 계약을 해석해 적절한 표현으로 내리고, 공통 최적화기는 그 표현 위에서 데이터 흐름·제어 흐름·메모리 사용을 바꾼다. 백엔드는 대상의 명령, 레지스터, 벡터 폭, 메모리 계층과 호출 규약에 맞게 낮춘다.

이 분리는 한 번 번역한 결과를 재사용하는 일만 뜻하지 않는다. 링크 시점 전역 분석, 프로파일 기반 변환, 계산 그래프의 연산자 융합처럼 서로 다른 시간·비용 예산의 변환도 공통 표현을 통해 연결할 수 있다. 다만 어떤 표현도 모든 언어의 고수준 의미와 모든 기계의 세부 제약을 동시에 완전하게 담지는 않는다.

## 의미 보존의 경계

중간 표현이 있다는 사실만으로 변환이 올바른 것은 아니다. 언어의 정의된 동작, 정수·부동소수점 규칙, 예외·메모리 규칙, 외부 호출과 관찰 가능한 순서가 무엇인지에 따라 허용되는 변환이 달라진다. 따라서 중간 표현은 의미를 자동으로 결정하는 보편 사양이 아니라, 지정된 계약 아래에서 분석과 변환을 수행하는 작업 공간이다.
