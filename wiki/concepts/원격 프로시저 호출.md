## 개요

[[원격 프로시저 호출]](RPC)은 다른 컴퓨터나 주소 공간에서 실행되는 연산을 로컬 프로시저 호출과 비슷한 인터페이스로 요청하는 방식이다. 호출자 스텁과 서버 스텁이 인수와 결과를 변환하고, 바인딩과 런타임이 목적지를 찾아 메시지를 교환한다. 이 구조는 인터페이스 사용을 단순하게 하지만, 네트워크를 통한 실행이 로컬 호출과 동일한 실행이 되는 것은 아니다.

[[Implementing Remote Procedure Calls]]은 RPC를 스텁, 인터페이스, 바인딩, 통신 런타임, 재전송, 중복 호출 처리의 조합으로 설명한다. 따라서 RPC는 하나의 함수 문법이 아니라, 호출 전후에 이름 해석·값 직렬화·전송·원격 실행·응답·오류 처리를 배치하는 시스템 계층이다.

## 로컬 호출과 다른 조건

| 항목 | 로컬 프로시저 호출 | 원격 프로시저 호출에서 추가되는 조건 |
|---|---|---|
| 실행 위치 | 보통 같은 프로세스·주소 공간에서 제어를 넘긴다 | 다른 프로세스·호스트에서 요청을 수신하고 실행한다 |
| 인수와 결과 | 호출 규약·메모리 표현을 공유할 수 있다 | 직렬화·역직렬화, 인터페이스 버전, 값 경계가 필요하다 |
| 대기 | 같은 실행 환경의 스케줄링·자원 경합이 주된 요인이다 | 네트워크 지연·혼잡·이름 해석·서버 큐·원격 실행이 더해진다 |
| 실패 관찰 | 제어 흐름과 프로세스 상태를 비교적 직접 관찰한다 | 시간 초과만으로 미수신·실행 중단·실행 후 응답 유실을 구분할 수 없다 |
| 재시도 | 같은 함수 본문을 다시 호출할지 명시적으로 정한다 | 자동·수동 재시도가 중복 원격 부작용을 만들 수 있다 |

RPC가 제공하는 추상화는 좋은 API를 만들 수 있지만, 이러한 차이를 숨긴 채 로컬 호출과 같은 오류 처리 방식으로 사용하면 잘못된 결과를 낳을 수 있다.

## 응답 부재와 재시도

호출자가 응답을 받지 못하면 요청이 전송되지 않았는지, 서버가 실행 전에 실패했는지, 실행 뒤 응답만 사라졌는지 일반적으로 알 수 없다. 이 상태는 “실패”라는 하나의 결과로 압축할 수 없다. 재시도 정책은 작업의 멱등성, 요청 식별자, 서버의 중복 제거 보존 기간, 외부 부작용과 보상 처리에 따라 달라진다.

따라서 RPC API에는 최소한 성공·실패·시간 초과의 의미, 재시도 주체와 횟수, 중복 실행 허용 여부, 취소의 의미, 관찰 가능한 작업 식별자를 함께 설계해야 한다. 이 계약은 [[종단 간 원칙]]이 말하는 응용 종단의 결과 확인과 연결된다.
