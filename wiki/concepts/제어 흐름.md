## 개요

[[제어 흐름]]은 프로그램의 명령들이 어떤 순서로 실행되는지를 가리킨다. 순차 실행, 조건 분기, 반복, 절차 호출, 복귀, 예외 탈출은 모두 실행 흐름을 바꾸거나 조직하는 방식이다.

## 역사적 흐름

초기 기계에서 제어 흐름은 주소와 점프 명령으로 직접 드러났다. [[Wheeler Jump]]는 서브루틴 호출 뒤 어디로 돌아갈지를 해결하는 방식이었고, [[스택]]은 중첩 호출과 재귀 호출에서 복귀 경로를 안정적으로 관리하는 수단이 되었다.

고급 언어에서는 같은 문제가 다른 형태로 나타난다. [[GOTO 문]]은 기계 수준의 점프를 언어 표면으로 끌어올리지만, [[구조적 프로그래밍]]은 실행 경로를 [[제어 구조]] 안에 가두어 사람이 프로그램 진행을 추적할 수 있게 한다.

## 제어 축의 하드웨어 메커니즘과 간접화

[[하드웨어 실행 모델]]에서 제어 흐름의 물리적 실체는 **프로그램 카운터**(PC / RIP)가 가리키는 주소에서 기계어 명령어를 인출(Fetch)하는 순차 사이클이다.

이 체계에서 간접 주소 지정(Indirect Addressing)은 저장 축과 제어 축 양쪽에서 대칭적인 추상화를 형성한다.

- **데이터 포인터:** **저장 축의 간접화**다. 고정된 변수 칸 대신 다른 데이터 셀의 주소를 가리켜 동적 데이터 접근을 가능하게 한다.
- **함수 포인터:** **제어 축의 간접화**다. 고정된 명령열 대신 런타임에 결정된 코드 위치의 주소로 PC를 이동시켜 동적 제어 전이를 가능하게 한다.

## 의미

제어 흐름은 단순히 다음에 실행할 명령을 고르는 문제가 아니다. 실행 중 어느 지점에서 변수 값이 어떤 의미를 갖는지, 오류가 어디서 생겼는지, 프로그램의 일부가 어떤 조건에서 올바른지를 설명하기 위한 기준이다.

## 관련 항목

- [[하드웨어 실행 모델]] — 연산(ALU)·저장(RAM)·제어(PC)의 3축 분리와 버스 분업 위에서 명령 사이클을 회전시키는 물리적 컴퓨터 동작 구조.
- [[제어 구조]] — 실행 흐름을 순차·선택·반복·절차 호출 같은 사람이 추적 가능한 형태로 제한하는 언어 장치.

- [[복귀 주소]] — 서브루틴이나 함수가 끝난 뒤 실행을 재개해야 할 위치를 가리키는 주소.
