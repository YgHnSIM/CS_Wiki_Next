## 개요

[[프레임버퍼 메모리 사상]](Framebuffer Memory Mapping)은 디스플레이 장치의 2차원 이산 직교 평면 상의 픽셀 좌표 $(x, y)$를 GPU 및 비디오 디스플레이 컨트롤러가 접근할 수 있는 VRAM의 1차원 물리 선형 메모리 주소로 1:1 대응시키는 컴퓨터 아키텍처의 핵심 메커니즘이다.

17세기 데카르트가 확립한 2차원 직교 좌표계는 인간의 시각 인터페이스를 지배하지만, 현대 컴퓨터의 폰 노이만 메모리 서브시스템은 1차원의 바이트 단위 선형 어드레싱만을 지원한다. 따라서 디스플레이의 모든 시각 정보는 매 프레임마다 엄격한 행 우선(Row-Major) 선형 대수 사상 공식에 의해 메모리 버스로 공급된다.

## 2D 좌표에서 1D 물리 주소로의 변환 공식

디스플레이의 해상도를 가로 $W$, 세로 $H$라 하고, 화면 좌측 상단을 원점 $(0, 0)$으로 둘 때, 임의의 픽셀 $(x, y)$ ($0 \le x < W, 0 \le y < H$)의 물리 메모리 바이트 주소는 다음과 같이 계산된다:

$$\text{Memory Address} = \text{Base Address} + (y \times \text{Stride} + x) \times \text{BytesPerPixel}$$

또는 바이트 단위의 주사선 폭인 $\text{Pitch}$($\text{Pitch} = \text{Stride} \times \text{BytesPerPixel}$)를 사용하면:

$$\text{Address}(x, y) = \text{Base Address} + y \times \text{Pitch} + x \times \text{BytesPerPixel}$$

```text
VRAM 물리 메모리 배치 (Row-Major 순서)
+------------------------------------------------------------------------+
| Base Address                                                           |
| v                                                                      |
| [Line 0: (0,0), (1,0), ..., (W-1,0)] [Padding]                         | <- 1 Pitch
| [Line 1: (0,1), (1,1), ..., (W-1,1)] [Padding]                         | <- 2 Pitch
| ...                                                                    |
| [Line y: (0,y), ..., (x,y), ..., (W-1,y)] [Padding]                   |
| ...                                                                    |
+------------------------------------------------------------------------+
```

- **Base Address**: VRAM 내 프레임버퍼 할당 시작 주소 (DMA 스캔아웃 레지스터에 기록됨).
- **BytesPerPixel (BPP)**:
  - `RGBA8888` / `BGRA8888`: 4 바이트 (32-bit 참색상).
  - `RGB565`: 2 바이트 (16-bit 고색상).
  - `RGBA16F`: 8 바이트 (64-bit 부동소수점 HDR 색상).
- **Stride**: 행당 할당된 유효 픽셀 및 패딩 픽셀의 합.

## Stride(Pitch)와 메모리 정렬의 하드웨어적 필연성

이론적으로는 $\text{Stride} = W$이어야 하지만, 실제 그래픽 하드웨어에서는 거의 항상 $\text{Pitch} \ge W \times \text{BytesPerPixel}$이며, 그 차이만큼의 패딩(Padding)이 행 끝에 추가된다.

### 정렬 요건의 원인

1. **캐시 라인(Cache Line) 정렬**:
   현대 CPU와 GPU의 L1/L2 캐시 라인은 대개 64바이트 또는 128바이트 크기다. 만약 주사선 시작 주소가 캐시 라인 경계에 일치하지 않으면, 첫 픽셀과 마지막 픽셀을 읽을 때 캐시 라인이 분할되어 2회의 메모리 트랜잭션이 발생하는 캐시 분할 접근(Split Access) 패널티가 발생한다.
2. **DRAM 버스트 전송(Burst Length)**:
   LPDDR4/LPDDR5 등 현대 메모리 컨트롤러는 최소 16바이트 또는 32바이트 단위의 버스트 모드로 데이터를 읽고 쓴다.
3. **디스플레이 컨트롤러 DMA 요구사항**:
   화면 주사율($60\text{Hz}, 120\text{Hz}$)에 맞추어 픽셀 데이터를 디스플레이 패널로 밀어내는 비디오 스캔아웃 DMA 엔진은 하드웨어적으로 64바이트, 128바이트, 또는 256바이트 정렬을 강제한다.

### 정렬 계산식

$$\text{Pitch} = \lfloor (W \times \text{BytesPerPixel} + A - 1) / A \rfloor \times A = (W \times \text{BytesPerPixel} + A - 1) \ \& \ \sim(A - 1)$$

단, 정렬 크기 $A$는 보통 $64$, $128$, 또는 $256$이다.

## 2D 공간 지역성과 캐시 계층 구조의 충돌

1차원 선형 프레임버퍼 배치는 수평 방향 픽셀 순회에는 매우 유리하지만, 2D 그래픽 연산(블러링, 필터링, 래스터화) 시 심각한 캐시 미스를 유발한다.

- **수평 인접 픽셀**: $(x, y)$와 $(x+1, y)$의 주소 차이는 불과 $4\text{바이트}$이므로 동일 캐시 라인에 적재되어 캐시 히트율이 극대화된다.
- **수직 인접 픽셀**: $(x, y)$와 $(x, y+1)$의 주소 차이는 수 킬로바이트($\text{Pitch} \approx 4\text{KB}\sim 8\text{KB}$)에 달하므로, 수직 순회 시 매 픽셀마다 캐시 라인을 새로 적재해야 하며 캐시 스래싱(Cache Thrashing)이 발생한다.

> [!TIP] 텍스처 타일링(Texture Tiling)의 해결책
> 현대 모바일 GPU는 VRAM 내부 렌더 타깃을 선형(Linear)이 아닌 $8 \times 8$ 또는 $16 \times 16$ 크기의 사각형 블록 단위로 묶는 **타일형 메모리 배치(Tiled Memory Layout / Morton Order)**를 적용하여 2차원 공간 지역성을 보존한다. 최종적으로 디스플레이 패널로 출력(Scanout)될 때만 선형 프레임버퍼로 변환된다.

## 3D 그래픽스 파이프라인과의 통합: 동차 좌표와 래스터라이저

3차원 기하 도형의 정점들은 $4 \times 4$ 동차 변환 행렬을 거쳐 정규화 장치 좌표(NDC, $[-1, 1]^3$)로 변환된 후, 뷰포트 변환(Viewport Transform)을 통해 화면 픽셀 좌표 $(x, y)$로 사상된다:

$$x = \frac{x_{\text{ndc}} + 1}{2} W, \quad y = \frac{1 - y_{\text{ndc}}}{2} H$$

하드웨어 래스터라이저는 이 $(x, y)$ 정수 격자에 대해 피네다(Pineda) 엣지 함수를 병렬 평가하여 프래그먼트의 포함 여부를 판정하고, 프레임버퍼 메모리 사상 공식을 통해 최종 픽셀 색상을 VRAM의 해당 주소에 기록(ROP: Raster Operations)한다.
