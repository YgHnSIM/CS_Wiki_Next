## 개요

[[ASLR]](Address Space Layout Randomization, 주소 공간 배치 무작위화)은 프로그램이 사용하는 주요 메모리 영역의 위치를 실행마다 달라지게 해 주소 예측 가능성을 낮추는 보안 완화 기법이다. 운영체제와 로더는 주소 범위·정렬·호환성 같은 제약 안에서 실행 파일, 공유 라이브러리, 스택, 힙, `mmap` 영역 등의 기준 위치를 선택할 수 있다.

ASLR의 핵심은 메모리 오류를 없애는 것이 아니다. [[메모리 안전성]]이 경계 밖 접근과 잘못된 수명을 막는 성질이라면, ASLR은 오류가 이미 발생할 수 있는 상황에서 중요한 주소를 미리 맞히기 어렵게 만드는 확률적 방어다. 따라서 ASLR이 켜져 있어도 메모리 안전성 문제가 사라지는 것은 아니다.

## 왜 필요한가

프로그램의 실행 흐름이나 데이터 위치가 고정되어 있으면, 어떤 메모리 주소를 가리켜야 하는지 미리 아는 오류가 더 쉽게 악용될 수 있다. 예를 들어 현대 호출 구조에서는 [[복귀 주소]]가 [[스택]]에 저장된다. 저장 위치와 코드 위치가 항상 같다면 주소를 전제로 한 공격이 쉬워지지만, ASLR은 그 전제를 흔든다.

저장소의 스택 원본은 ASLR을 코드와 스택 주소를 예측하기 어렵게 하는 기법으로 설명한다. 이 설명은 ASLR의 역할을 “실행 권한을 바꾸는 것”이 아니라 “주소의 예측 가능성을 낮추는 것”으로 구분하는 직접 근거다.

## 무엇을 무작위화하는가

구체적인 대상과 정도는 운영체제·아키텍처·실행 파일 형식·정책에 따라 달라진다. Linux 커널 문서와 PaX 설계 문서를 종합하면 입문자는 다음처럼 이해할 수 있다.

| 영역 | 의미 | ASLR에서의 역할 |
|---|---|---|
| 실행 파일 코드 | 프로그램의 명령과 정적 데이터가 놓이는 영역 | PIE로 연결된 실행 파일은 코드 시작 위치도 무작위화될 수 있다. |
| 공유 라이브러리·`mmap` 영역 | 동적으로 매핑되는 라이브러리와 메모리 영역 | 기준 위치를 달리해 라이브러리와 매핑 영역의 주소 예측을 어렵게 한다. |
| 스택 | 호출 상태, 지역 데이터, 복귀 주소가 놓이는 영역 | 스택의 기준 위치를 달리해 고정된 스택 주소에 대한 가정을 약화한다. |
| 힙 | 동적으로 할당되는 데이터 영역 | 운영체제 정책에 따라 힙의 배치도 무작위화될 수 있다. |
| 커널 주소 공간 | 운영체제가 커널 코드·데이터를 사용하는 영역 | KASLR은 부팅 시 커널의 기준 주소를 옮기는 별도의 적용 형태다. |

표의 주소값과 대상은 모든 시스템에 동일하게 적용되는 고정 목록이 아니다. 예를 들어 Linux의 프로세스 정책은 `mmap` 기준 위치·스택·VDSO·공유 라이브러리·PIE 코드 시작 위치와 힙을 서로 다른 조건에서 다룬다.

## 작동 원리

ASLR은 대략 다음 순서로 이해할 수 있다.

1. 운영체제와 로더가 실행 파일과 프로세스의 메모리 배치를 준비한다.
2. 각 영역에 적용할 수 있는 주소 범위와 정렬 조건 안에서 기준 위치 또는 오프셋을 선택한다.
3. 실행 파일이 여러 위치에서 동작할 수 있도록 필요한 relocation·position-independent code 지원을 사용한다.
4. 프로그램 내부의 상대적 구조는 유지하면서, 실행마다 관찰되는 절대 위치는 달라질 수 있게 한다.

여기서 [[재배치]]와 ASLR을 같은 것으로 보면 안 된다. 재배치는 코드가 실제 적재 위치에 맞도록 주소를 보정하는 메커니즘이고, ASLR은 그 적재 위치 자체를 예측하기 어렵게 선택하는 보안 정책이다. [[로더]]는 실행 파일과 공유 라이브러리를 메모리에 배치하는 계층으로서 두 작업이 만나는 지점이다.

### 추상적인 실행 비교

아래 값은 실제 운영체제의 주소나 디버거 출력이 아니라, 영역의 기준 위치가 달라지는 모습을 보여 주기 위한 합성 예시다.

| 실행 | 코드 | 공유 라이브러리 | 힙 | 스택 |
|---|---:|---:|---:|---:|
| 실행 A | `0x1000` | `0x4000` | `0x7000` | `0xB000` |
| 실행 B | `0x3000` | `0x6000` | `0x9000` | `0xD000` |

실행 A와 B에서 같은 프로그램의 영역이 서로 다른 기준 위치에 놓일 수 있다는 점이 핵심이다. 그렇다고 모든 바이트가 독립적으로 무작위화되거나, 모든 영역이 항상 같은 폭으로 이동한다는 뜻은 아니다. 실제 선택은 주소 공간의 제약과 운영체제 정책을 따른다.

## 엔트로피와 한계

ASLR에서 엔트로피(entropy)는 공격자가 주소를 추측해야 하는 가능한 배치의 불확실성을 설명하는 직관적인 개념이다. 가능한 기준 위치가 많고 서로 충분히 다르면 고정 주소를 전제로 한 추측은 어려워진다. 반대로 주소 범위가 좁거나, 정렬·호환성 제약이 크거나, 여러 영역의 배치가 서로 강하게 연결되면 실제 불확실성은 줄어든다.

ASLR은 다음 이유로 완전한 방어가 아니다.

- **정보 노출:** 실행 중 주소가 외부로 노출되면 무작위화된 기준 위치를 추론할 수 있다. Linux 커널 자기 보호 문서도 정보 노출이 KASLR의 의미를 약화시킬 수 있다고 설명한다.
- **낮은 엔트로피:** 가능한 위치의 수가 적으면 추측에 필요한 불확실성이 작다.
- **부분 무작위화:** 정책이나 호환성 때문에 일부 영역만 무작위화될 수 있다.
- **오류 자체의 존속:** ASLR은 경계 밖 접근, 잘못된 수명, 잘못된 포인터 같은 메모리 안전성 문제를 고치지 않는다.

따라서 ASLR은 다른 완화 기법, 안전한 구현 관행, 메모리 안전성을 보장하는 언어·도구와 함께 사용해야 하는 방어 계층이다.

## 관련 완화 기법과의 구분

| 기법 | 주로 바꾸는 것 | ASLR과의 관계 |
|---|---|---|
| ASLR | 메모리 영역의 위치 | 주소를 예측하기 어렵게 만든다. |
| `PIE` | 실행 파일 코드가 놓일 수 있는 방식 | 위치 독립적인 실행 파일은 메인 코드도 가변 위치에 놓일 수 있게 해 ASLR의 적용 범위를 넓힌다. `PIE` 자체가 전체 프로세스 주소 공간을 무작위화하는 정책은 아니다. |
| `DEP/NX` | 메모리 영역의 실행 권한 | 데이터 영역을 코드로 실행하기 어렵게 만든다. 주소를 숨기는 ASLR과 방어 목표가 다르다. |
| `KASLR` | 커널의 기준 주소 | 사용자 프로세스가 아니라 부팅 시 커널 주소 공간에 적용하는 ASLR의 변형이다. |
| 메모리 안전성 | 경계·수명·참조의 유효성 | 오류가 발생할 가능성을 줄이거나 제거하는 성질이며, ASLR의 주소 불확실성과는 다른 계층이다. |

특히 `PIE`와 ASLR은 서로 대체 관계가 아니다. 실행 파일이 위치 독립적으로 만들어져야 메인 실행 코드의 기준 위치를 바꾸기 쉽고, 운영체제·로더의 ASLR 정책이 실제 위치 선택을 수행한다.

## 역사와 적용 범위

ASLR의 설계와 적용은 운영체제 보안 완화의 역사 속에서 발전했다. 이 문서에서 확인하는 역사적 기준점은 PaX Team이 2003년에 공개한 ASLR 설계 문서다. PaX 자료는 사용자 공간을 여러 영역으로 나누고 각 영역의 기준 위치를 달리하는 설계를 보여 준다.

오늘날에는 사용자 프로세스 주소 공간을 다루는 ASLR과 커널의 부팅 시 기준 주소를 다루는 KASLR을 구분해야 한다. 두 기법 모두 주소 예측 가능성을 낮추지만, 적용 대상·시점·구현 제약이 다르다. 플랫폼별 도입 연도와 설정값은 이 개념 문서의 범위를 넘는다.
