## 개요

[[순차 일관성]](sequential consistency)은 다중 프로세서 공유 메모리의 실행 결과가 모든 메모리 연산을 어떤 하나의 순차적 순서로 실행한 결과와 같고 그 순서 안에서 각 프로세서의 연산은 자기 프로그램이 지정한 순서를 보존해야 한다는 조건이다. 이는 실제 하드웨어가 한 번에 하나의 연산만 수행해야 한다는 뜻이 아니라 관찰 가능한 읽기·쓰기 결과를 설명할 수 있는 전역 순서가 있어야 한다는 뜻이다.

이 조건은 각 프로세서 안에서 명령이 순차적으로 보이는 문제보다 강하다. 서로 다른 프로세서가 공유 변수에 수행한 읽기·쓰기는 동기화 알고리즘의 전제가 되므로 프로세서별 순서와 시스템 전체의 관찰 순서를 함께 규정해야 한다.

## 정의의 구성

순차 일관성은 두 요구를 결합한다.

1. **프로그램 순서 보존:** 한 프로세서가 프로그램에서 먼저 수행한 메모리 연산은 전역 순서에서도 그 뒤 연산보다 앞선다.
2. **하나의 전역 순서:** 모든 프로세서의 메모리 연산은 한 순차적 실행으로 배열할 수 있고, 각 읽기는 그 순서에서 허용되는 값을 관찰한다.

이 정의는 메모리 연산을 대상으로 한다. 큐의 `enqueue`, 계정의 `withdraw`처럼 여러 읽기·쓰기로 이루어진 API 호출 전체가 외부에서 어떤 순서로 보이는지는 [[선형화 가능성]]처럼 객체 수준에서 별도로 정해야 한다.

## 선형화 가능성과의 차이

| 조건 | 주된 단위 | 보존하는 순서 | 직접 보장하지 않는 것 |
|---|---|---|---|
| 순차 일관성 | 프로세서의 메모리 읽기·쓰기 | 각 프로세서의 프로그램 순서와 하나의 전역 순서 | 서로 다른 실행 주체의 겹치지 않은 고수준 연산에 대한 실제 시간 순서 |
| 선형화 가능성 | 추상 객체의 호출·응답 이력 | 객체 명세와 겹치지 않은 연산의 실제 시간 순서 | 메모리 모듈·캐시·컴파일러가 어떤 구현으로 이를 달성하는지 |

따라서 순차 일관성이 곧 모든 API의 원자성이라는 말은 정확하지 않다. 반대로 선형화 가능한 객체 구현도 어느 메모리 모형과 동기화 원시 연산 위에서 작동하는지는 별도로 밝혀야 한다.

## 측정·설계 경계

순차 일관성은 처리량, 평균 지연, 전력, 공정성, 장애 복구의 지표가 아니다. 어떤 시스템이 이 조건을 제공한다고 말할 때는 적어도 다음을 분리해야 한다.

- 적용 단위가 프로세서의 읽기·쓰기인지, 언어의 원자 연산인지, API 호출인지
- 프로그램 순서에 포함되는 연산과 동기화 경계가 무엇인지
- 캐시·컴파일러·런타임의 재배치가 어떤 규칙 아래 허용되는지
- 성능 비교에서 대기·동기화·데이터 이동을 포함했는지

이렇게 해야 [[캐시 메모리]]의 빠른 사본, [[상호 배제와 동기화]]의 임계 구역, 객체 인터페이스의 결과 계약을 같은 종류의 “일관성”으로 혼동하지 않게 된다.
