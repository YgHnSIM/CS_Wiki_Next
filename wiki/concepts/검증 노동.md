## 개요

[[검증 노동]]은 도구가 만든 코드·계산 결과·설계 제안이 유효한지 확인하고 실제 시스템에 통합하는 데 필요한 사람의 작업이다. 여기에는 생성 결과를 읽고 의미를 이해하는 일, 요구사항과 비교하는 일, 테스트·리뷰·문서화·배포를 관찰하는 일, 문제를 발견한 뒤 수정하는 일이 포함된다.

생성 시간이 줄어도 검증 노동이 같은 비율로 줄어드는 것은 아니다. 도구의 제안이 현재 코드베이스의 규약, 보안 경계, 성능·운영 제약에 맞는지 판단하려면 맥락 지식과 결과 계약이 필요하다. 반대로 검증 도구도 일부 노동을 줄일 수 있으므로 “AI가 검토를 늘린다”는 일반 명제 대신 어떤 단계와 기준이 바뀌었는지 기록해야 한다.

| 작업 | 확인 대상 | 흔한 누락 |
|---|---|---|
| 이해·편집 | 제안의 의도와 실제 동작 | 문법적 통과를 의미적 적합성으로 오인 |
| 테스트 | 정상·경계·실패 조건 | 자동 테스트 통과를 모든 요구 충족으로 오인 |
| 리뷰·통합 | 저장소 규약, 문서, 의존성 | 독립 예제를 실제 시스템 맥락으로 일반화 |
| 운영 관찰 | 배포 뒤 성능·오류·복구 | 구현 완료를 서비스 결과 완료로 오인 |
