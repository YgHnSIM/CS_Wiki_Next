Node 기반 위키 린트와 유지보수 도구를 import 가능한 검사·수정 코어와 얇은 CLI로 분리했다. 테스트가 실제 운영 진입점을 직접 호출할 수 있게 되었고, import만으로 검사나 파일 쓰기가 실행되지 않도록 경계를 명확히 했다.

배포 자산 버전은 JavaScript 파일 이름을 손으로 나열하는 방식에서 `site/assets/` 전체와 생성 CSS를 상대 경로·원본 바이트 기준으로 해시하는 방식으로 바꿨다. 새 런타임 모듈, 글꼴, 아이콘 같은 자산을 추가하거나 이름을 바꿔도 캐시 무효화 지문에 자동 반영된다.

### 변경된 파일

- 사이트 빌드: `site/build.mjs`, `site/asset-fingerprint.mjs`
- 위키 도구: `scripts/wiki_lint.mjs`, `scripts/wiki_maintenance.mjs`
- 회귀 테스트: `tests/site-asset-fingerprint.test.mjs`, `tests/wiki-lint.test.mjs`, `tests/wiki-maintenance.test.mjs`
- 작업 기록: `wiki/logs/`, [[작업 로그]]

### 주요 개선

- 계획된 빨간 링크는 미해결 링크 오류에서 제외하고, 같은 미해결 링크를 한 번만 보고한다.
- 린트 JSON의 `pages`에 실제 매니페스트 페이지 수를 기록한다.
- 로컬 근거 경로는 어휘적 경로와 실제 경로가 모두 `raw/` 안에 있는지 확인하고, 일반 파일 확인 뒤에만 읽고 해시한다.
- 전체 활성 문서의 `updated`가 실행 당일이어야 한다는 전역 유지보수 검사를 제거하고, 수정 문서의 날짜 정책은 변경 집합 검증에 맡긴다.
- EOL 수정은 명시적 함수로 분리하고 revision 재계산, LF, 마지막 줄바꿈을 보존한다.

### 검증

- 신규 Node 회귀 테스트 14개 통과
- 전체 Node 테스트 145개와 Python 호환성 테스트 24개 통과
- 341개 위키 페이지 빌드와 정적 산출물 검증 통과
- Chromium 브라우저·접근성 테스트 17개 통과
- 위키 lint와 유지보수 검사 모두 오류 없음
- `raw/` 원본 변경 없음
