입력값이 시스템을 통과할 때 디코드·파싱·정규화·검증·인가·출력 처리는 서로 다른 계약임을 분리하고, Unicode 식별자와 C의 길이·정수 계산을 하나의 해석 경계로 연결했다. 형식에 맞는 입력도 다른 표현·다른 단위·파생된 연산값으로 소비되면 안전하다는 결론을 낼 수 없다는 점을 명시했다.

### 검증

- 정규화는 표현 동등성 정책이고, 입력 검증·인가·출력 이스케이프/인코딩과 같은 조치가 아님을 구분했다.
- 동형이의 문자 탐지는 신원 동등성이나 권한 증명을 대신하지 않으며, 스크립트·표시·중복 등록 정책과 분리했다.
- 정수 검증은 입력값 하나뿐 아니라 `개수 × 크기`, `오프셋 + 길이` 같은 파생값, 타입 변환, signed/unsigned의 언어 의미론까지 다뤄야 함을 기록했다.
- CWE-20·CWE-190의 MITRE 원전 URL은 모두 200으로 확인했다. 전체 링크 점검의 두 404는 새 자료가 아니라 P5 출처 보존 대기열의 기존 NIST 링크다.
- `npm run check`는 296페이지·7,315링크, Node 153개·Python 23개·브라우저 5개 테스트를 통과했다. 정적 출력도 학습선 22개·정류장 245개, 2,901파일·72.82 MiB로 검증했다.
